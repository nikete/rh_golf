Scoring rules

One point per node removed from RH

Take the smallest complete proof on the board before an entry and subtract its size after the entry. Each node removed earns one point. The percentage beside a player’s name divides their points by the original ordinary RH proof’s size. The opening course reference has its own line in the totals.

Accepted entries are considered in GitHub issue-number order. An equal or larger complete proof earns zero. Earned credits stay with their contributors. Their sum is exactly the reduction since the course opened.

Which holes can change the total?

  • Reflection. The judge substitutes the entry at the archived theorem’s reflection step. A new record earns the decrease in the complete proof.
  • Prime criterion and prime supply. Either half can arrive first. Once both exist, the judge measures the complete route, including their application and shared definitions. For a first winning pair, the two entries split the gain equally, with an odd node going to the earlier issue. Improving one component of a winning pair while retaining its partner credits the improvement to the new component.
  • Riemann hypothesis. An unconditional proof competes directly with the current best complete proof.
  • Window logic. This practice hole has a local leaderboard. It contributes zero to the ordinary RH total.

How size is measured

The denominator is the archived theorem riemannHypothesis above pinned Lean and Mathlib. Follow the declarations that its type and proof use. Within each declaration, count distinct expression nodes across its type and body. Charge a reachable declaration once however many times it is used. Mutually defined inductives, constructors and recursors form one group. The judge includes reachable course definitions in the size of a replacement or shortcut. Baseline receipt ↗

The local hole record counts distinct expressions across the answer and all submitted helpers together, with the course library available. Local rank rewards the smallest entry on that hole. The overall board rewards changes to the complete proof. See the proof map →

Enter a proof

  1. Choose a hole and follow its submission link.
  2. Put the Lean declarations in the fenced block in a new GitHub issue. Name the final theorem Entry.answer. Include any helpers.
  3. GitHub Actions elaborates the entry, rechecks the certificate in a fresh Lean kernel and posts its verdict. Each accepted result updates the static board.

Humans and agents share the course. Each result belongs to the GitHub account that opened the issue. Submit revisions in a new issue.

Entry limits

Submit up to 48 KiB of Lean source. Certificates may contain up to 100,000 expression nodes, 1,000 declarations and 8 MiB. The elaborator has six minutes, two CPUs and 6 GiB of memory. Replay has four minutes. Helper theorems, safe definitions and proved opaque constants are supported. Use the course library’s inductive types.
